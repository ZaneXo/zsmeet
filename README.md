# zsmeet

开源、自己部署的会议纪要系统。在网页上录音或者上传录音文件，服务器自动转成文字、区分说话人，再用大模型写成纪要。

- **录音不出你的服务器**：语音识别在本机 CPU 上完成，不调用外部服务。只有转写出来的文字会发给你配置的大模型；用自己部署的模型（Ollama、vLLM），数据就完全不出内网。
- **一条命令部署**：`docker compose up -d`，三个容器（数据库、网页和接口、后台处理），不需要 GPU。
- **纪要可追溯**：每次编辑、每次重新生成都是一个新版本，旧版本一直保留。纪要里的时间点可以点，直接跳到录音对应的位置。

> 项目还在早期。目前能做的：网页录音或上传录音 → 转写 → 纪要 → 在网页上查看和编辑，以及邀请同事一起用。
> 飞书集成等见下面的[路线图](#路线图)。

## 部署

需要一台装了 Docker 的 Linux 服务器，建议 4 核 CPU、8 GB 内存以上。

```bash
git clone <本仓库地址> zsmeet && cd zsmeet/deploy
cp .env.example .env
# 编辑 .env，填两个密码（文件里有生成方法）
docker compose up -d --build
```

然后用浏览器打开 `http://服务器地址:8080`：

1. 第一次打开会让你创建管理员账号。
2. 进入「设置」，填写大模型的接口地址、模型名和 API Key，点「测试连接」确认能用后保存。
   任何 OpenAI 兼容的接口都可以。不配置也能用，只是只有转写、没有纪要。
3. 回到「会议」，开始录音，或者上传一段录音。
4. 进入「设置 → 成员」邀请同事（见下面的[成员](#成员)）。

第一次处理会议时，后台会下载约 560 MB 的识别模型（来自 Hugging Face，连不上时自动换国内镜像），之后不用再等。

**升级**：`git pull && docker compose up -d --build`，数据库会自动迁移。

**备份**：数据在三个 Docker 数据卷里。`zsmeet_pgdata` 是数据库，`zsmeet_data` 是录音，这两个要备份；`zsmeet_models` 是识别模型，丢了会重新下载。另外请保管好 `.env` 里的 `ZSMEET_SECRET_KEY`，没有它就解不开数据库里保存的 API Key。

**HTTPS**：浏览器只允许 HTTPS 网页使用麦克风，所以要用网页录音，就得在前面加一层 HTTPS 反向代理（Caddy、Nginx 等），并把 `.env` 里的 `ZSMEET_SECURE_COOKIE` 设为 `true`。只用 `http://服务器地址:8080` 打开的话，上传录音、查看纪要都正常，只是不能录音（在服务器本机上用 `http://localhost:8080` 打开可以录）。

**安全**：在第一个人创建管理员之前，任何能访问这个地址的人都可以成为管理员，所以部署后请尽快完成初始化。对公网开放时一定要用 HTTPS（见上一条）。

### 网页录音

点「开始录音」，选录什么声音：

- **只录麦克风**：线下会议室、面对面聊天。电脑或手机放在桌子中间效果最好。
- **麦克风 + 浏览器标签页的声音**：在浏览器里开的线上会议（网页版的飞书会议、腾讯会议、Google Meet 等）。开始后选中会议所在的标签页，并打开「同时共享标签页音频」。只有电脑上的 Chrome 和 Edge 支持。用桌面版会议软件开会时浏览器录不到对方的声音，请用会议软件自带的录制，会后上传。

录音每 10 秒切一片，先存在这台电脑的浏览器里，再传到服务器：

- **断网不丢**：断网时录音照常进行，分片留在电脑上，网络恢复后自动补传。点「结束录音」后等剩下的传完，就自动开始处理。
- **网页关了也不丢**：录音中途关掉了网页、浏览器崩溃了，下次在这台电脑上打开 zsmeet，顶部会提示有一段录音没传完，可以接着传，也可以下载到电脑上。最多丢掉关掉前的最后 10 秒左右。
- **电脑找不回来了**：已经传到服务器的部分还在。会议的创建者或管理员打开这场会议，可以用已经收到的部分生成纪要。
- **标记重点**：录音时有人说到关键内容，点「标记重点」。纪要会把这些时间点前后的讨论写清楚，会议页面上也能直接跳过去听。
- 录音期间可以切到别的标签页，也可以在 zsmeet 里看别的页面。单场最长约 6 小时。

### 成员

zsmeet 不发邮件。邀请同事、帮人重置密码，都是由管理员生成一个一次性的链接，再自己通过飞书、微信等发给对方。

- **邀请**：「设置 → 成员 → 邀请成员」，填对方的邮箱、选角色，得到一个邀请链接（7 天内有效，只能用一次）。对方打开后填姓名和密码就加入了。链接只在生成时显示一次；弄丢了或者过期了，在「还没接受的邀请」里重新生成。
- **角色**：成员可以上传会议、查看全部会议。管理员还能管理成员、配置大模型。
- **谁能改会议**：所有成员都能看全部会议；修改（改标题、编辑纪要、重新生成）只有会议的创建者和管理员可以。
- **忘了密码**：管理员在成员列表里点「重置密码」，把生成的链接（24 小时内有效）发给他。自己记得密码、只是想换，在「设置 → 账号」里改。改密码后，这个账号在其他设备上的登录会全部退出。
- **有人离开团队**：在成员列表里停用他。他会立刻被退出登录，之后也登录不了；他创建的会议都还在。以后重新启用的话，他需要重新登录，停用前的登录不会恢复。
- **链接的安全**：拿到重置密码链接的人能直接进那个账号，所以成员列表会显示谁名下有一个还没用的，可以随时撤销。管理员被降级或停用时，他发出去还没用掉的邀请和重置链接会一起失效；邀请还留在「还没接受的邀请」里，别的管理员重新生成一个链接就能接着用。
- **登录有效期**：登录后 30 天内不用再输密码，到期重新登录。

没有管理员能登录了怎么办（唯一的管理员忘了密码，或者离职没交接）：在服务器上执行下面的命令。

```bash
cd zsmeet/deploy
docker compose exec api zsmeet reset-link 某人的邮箱   # 给这个账号生成重置密码的链接
docker compose exec api zsmeet make-admin 某人的邮箱   # 把这个账号设为管理员
```

### 处理要多久

识别在 CPU 上跑，不需要显卡。一组参考数据（Apple Silicon 笔记本上的 Docker，4 个线程，一段 20 分钟的两人对话）：

| 步骤 | 用时 |
|---|---|
| 接收与转码 | 9 秒 |
| 识别文字 | 13 秒 |
| 区分说话人 | 46 秒 |
| 合计（不含写纪要） | 约 1 分 10 秒 |

写纪要的时间取决于你用的大模型。普通的 x86 服务器会比这慢。

内存：worker 加载模型后常驻约 1 GB。另外一场录音会整段读进内存，每小时约占 230 MB，所以单场上限是 6 小时。

## 它是怎么工作的

```
浏览器 ──分片上传──▶  api（zsmeet serve）  ──任务入队──▶  Postgres
   ▲                    网页 · 接口 · 登录                    │
   │                                                          ▼
   └──── 进度推送 ◀──── 读数据库里的进度 ◀──── worker（zsmeet worker）
                                              拼接分片 → ffmpeg 转码 → 识别文字
                                              → 区分说话人 → 大模型写纪要
```

- `api` 和 `worker` 是同一个程序的两种启动方式，镜像也是同一个。
- 任务队列用 [River](https://riverqueue.com)，任务就存在 Postgres 里，不需要 Redis。
  「把会议改成排队中」和「任务入队」在同一个事务里，不会出现改了状态却没有任务的情况。
- worker 处理期间定时写心跳。worker 被杀掉或者机器重启时，心跳一停，巡检任务会在两三分钟内把会议重新入队，不用人工处理。
- 语音识别用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)：Silero VAD 切句、Paraformer 识别中文、CT-Transformer 加标点、pyannote + CAM++ 区分说话人。

## 开发

需要 Go 1.26、Node 24 + pnpm、Docker、ffmpeg。

```bash
make dev-api      # 终端 1：接口服务（会顺带起一个开发用的 Postgres）
make dev-worker   # 终端 2：后台处理
make dev-web      # 终端 3：前端，打开 http://127.0.0.1:5173
make test         # 跑全部测试
make help         # 看所有命令
```

### 目录

```
cmd/app/            程序入口：serve、worker，以及 models、openapi、reset-link 等辅助命令
internal/
  api/              HTTP 接口（huma）。只做取参数、调 service、转成响应
  service/          业务逻辑：账号、成员、会议、纪要版本、团队设置。不认识 HTTP
  pipeline/         后台处理一场会议的全过程，以及卡住时的自动恢复
  asr/              语音识别（sherpa-onnx，cgo）
  minutes/          纪要模板和提示词
  llm/              调用 OpenAI 兼容接口
  db/               表结构迁移（migrations/）、SQL（queries/）、sqlc 生成的代码（sqlc/）
  …                 其余是各管一件小事的包：audio、models、search、storage、secret、settings
web/                前端：React + TypeScript + Tailwind
deploy/             Dockerfile、docker-compose.yml、.env.example
tools/newapi/       make api 用的接口骨架生成器
```

### 加一个接口

```bash
make api NAME=DeleteMeeting METHOD=DELETE ROUTE=/api/meetings/{id}
```

会生成 `internal/api/delete_meeting.go`（输入输出结构体、接口说明、返回 501 的处理函数）和对应的测试，并注册好路由。接下来：

1. 在生成的文件里填请求和返回的字段。这些结构体就是前后端的约定，参数校验和接口文档都从它来。
2. 在 `internal/service` 里写业务逻辑，处理函数里调用它。
3. 补测试，然后 `make gen`：接口文档（`web/openapi.json`）和前端的 TypeScript 类型（`web/src/api/schema.d.ts`）会一起更新。前端用到了改动的字段，编译时就会报错。

改数据库：在 `internal/db/migrations` 里加一个迁移文件，在 `internal/db/queries` 里写 SQL，然后 `make gen`。

### 几条约定

- 接口框架 huma 只出现在 `internal/api` 里，业务逻辑写在 `internal/service`。有测试守着这条规则（`internal/arch`），以后要换框架只需要重写接口层。
- 给用户看的文字（报错、提示）都写成能照着处理的中文，不把内部报错直接抛给用户。
- 生成的文件（sqlc 的代码、`openapi.json`、`schema.d.ts`）都提交进仓库，`make test` 和 `make check` 会检查它们是不是最新的。
- 网页里的站内链接用 `AppLink`（`web/src/components/AppLink.tsx`），不直接用 react-router 的 `Link`：用户按住 Option 点 `Link` 时，浏览器会下载一个没用的网页空壳。`make check` 会检查。
