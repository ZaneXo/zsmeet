# zsmeet

开源、自己部署的会议纪要系统。在网页上录音或者上传录音文件，服务器自动转成文字、区分说话人，再用大模型写成纪要。

- **录音不出你的服务器**：语音识别在本机 CPU 上完成，不调用外部服务。只有转写出来的文字会发给你配置的大模型；用自己部署的模型（Ollama、vLLM），数据就完全不出内网。
- **一条命令部署**：`docker compose up -d`，三个容器（数据库、网页和接口、后台处理），不需要 GPU。
- **纪要可追溯**：每次编辑、每次重新生成都是一个新版本，旧版本一直保留。纪要里的时间点可以点，直接跳到录音对应的位置。

> 项目还在早期。目前能做的：网页录音或上传录音 → 转写 → 纪要 → 在网页上查看、编辑、搜索、提问、导出，以及邀请同事一起用。
> 可以接上飞书：纪要推到群里、导入成飞书文档、自动导入飞书会议的录制、用飞书扫码登录（见[飞书](#飞书)）；也能把纪要发到钉钉、企业微信、Slack 的群里（见[群机器人](#群机器人钉钉--企业微信--slack)）。还没做的见[路线图](#路线图)。

## 部署

需要一台装了 Docker 的服务器（x86 的 Linux，或者 Apple 芯片的 Mac 装 Docker Desktop / OrbStack），建议 4 核 CPU、8 GB 内存以上。

```bash
git clone https://github.com/ZaneXo/zsmeet.git && cd zsmeet/deploy
cp .env.example .env
# 编辑 .env，填两个密码（文件里有生成方法）
docker compose up -d --build
```

不想在服务器上构建的话，可以用发布好的镜像（同一个镜像里有 linux/amd64 和 linux/arm64）：在 `.env` 里加一行 `ZSMEET_IMAGE=ghcr.io/zanexo/zsmeet:0.1.0`（换成 [Releases](https://github.com/ZaneXo/zsmeet/releases) 里最新的版本号），再用 `docker compose pull && docker compose up -d --no-build` 代替上面最后一行。

然后用浏览器打开 `http://服务器地址:8080`：

1. 第一次打开会让你创建管理员账号。
2. 进入「设置」，填写大模型的接口地址、模型名和 API Key，点「测试连接」确认能用后保存。
   任何 OpenAI 兼容的接口都可以。不配置也能用，只是只有转写、没有纪要。
   「上下文长度」选模型一次能读多少（看模型的说明，默认 32K；Ollama 的本地模型没调大 `num_ctx` 的话一般只有 8K 到 32K）。
   长会议放不进一次请求时，先分段提取要点再汇总成纪要：32K 时每段约 2 万字，8K 约 3000 字，64K 约 5 万字，再长也最多 6 万字一段（一次塞太多，本地模型要算很久）。
   各段要点合起来也放不下时（上下文小、会又特别长），先把相邻几段的要点合并精简，一层层合到放得下再汇总，所以会多调用几次大模型。
   「问会议」交给大模型的材料也按它算，32K 时约 1.2 万字。选得比模型实际的大，长会议的纪要可能写不出来或者漏掉内容。
3. 回到「会议」，开始录音，或者上传一段录音。
4. 进入「设置 → 成员」邀请同事（见下面的[成员](#成员)）。

第一次处理会议时，后台会下载约 280 MB 的识别模型（来自 Hugging Face，连不上时自动换国内镜像），之后不用再等。

**升级**：`git pull && docker compose up -d --build`，数据库会自动迁移。用发布好的镜像的话，把 `.env` 里 `ZSMEET_IMAGE` 的版本号改成新的，再执行 `docker compose pull && docker compose up -d --no-build`。

**备份**：数据在三个 Docker 数据卷里。`zsmeet_pgdata` 是数据库，`zsmeet_data` 是录音，这两个要备份；`zsmeet_models` 是识别模型，丢了会重新下载。另外请保管好 `.env` 里的 `ZSMEET_SECRET_KEY`，没有它就解不开数据库里保存的 API Key。

**HTTPS**：浏览器只允许 HTTPS 网页使用麦克风，所以要用网页录音，就得在前面加一层 HTTPS 反向代理（Caddy、Nginx 等），并把 `.env` 里的 `ZSMEET_SECURE_COOKIE` 设为 `true`。只用 `http://服务器地址:8080` 打开的话，上传录音、查看纪要都正常，只是不能录音（在服务器本机上用 `http://localhost:8080` 打开可以录）。

反向代理要把访问者的 IP 用 `X-Forwarded-For` 带过来（Caddy 默认就带；Nginx 要加 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`），还要在 `.env` 的 `ZSMEET_TRUSTED_PROXIES` 里写上代理连过来的地址，zsmeet 才按真实的访问者 IP 限制输错密码的次数。默认只信本机（`127.0.0.1`、`::1`）。用 docker compose 部署、代理装在同一台机器上时，代理是从 Docker 网桥的网关连进容器的：把网关的地址（`docker network inspect zsmeet_default` 里的 `Gateway`，比如 `172.18.0.1`）写进 `ZSMEET_TRUSTED_PROXIES`，同时设 `ZSMEET_PORT=127.0.0.1:8080`，让 zsmeet 的端口只有本机的代理能连，别人绕过代理直接连端口就没法假装成别的 IP。没配好时（内网地址带着 `X-Forwarded-For` 连过来、却不在名单里），zsmeet 不按 IP 限制、只按账号限制，并在日志里提醒一次；外网地址发来的 `X-Forwarded-For` 一律不信。

**安全**：在第一个人创建管理员之前，任何能访问这个地址的人都可以成为管理员，所以部署后请尽快完成初始化。对公网开放时一定要用 HTTPS（见上一条）。

### 网页录音

点「开始录音」，选录什么声音：

- **只录麦克风**：线下会议室、面对面聊天。电脑或手机放在桌子中间效果最好。
- **麦克风 + 浏览器标签页的声音**：在浏览器里开的线上会议（网页版的飞书会议、腾讯会议、Google Meet 等）。开始后选中会议所在的标签页，并打开「同时共享标签页音频」。只有电脑上的 Chrome 和 Edge 支持。用桌面版会议软件开会时浏览器录不到对方的声音，请用会议软件自带的录制，会后上传。

录音每 10 秒切一片，先存在这台电脑的浏览器里，再传到服务器：

- **断网不丢**：断网时录音照常进行，分片留在电脑上，网络恢复后自动补传。点「结束录音」后等剩下的传完，就自动开始处理。
- **网页关了也不丢**：录音中途关掉了网页、浏览器崩溃了，下次在这台电脑上打开 zsmeet，顶部会提示有一段录音没传完，可以接着传，也可以下载到电脑上。最多丢掉关掉前的最后 10 秒左右。
- **电脑找不回来了**：已经传到服务器的部分还在。会议的创建者或管理员打开这场会议，可以用已经收到的部分生成纪要。
- **标记重点**：录音时有人说到关键内容，点「标记重点」。纪要会把这些时间点前后的讨论写清楚，会议页面上也能直接跳过去听。
- 录音期间可以切到别的标签页，也可以在 zsmeet 里看别的页面。单场最长约 6 小时。

### 会议

- **给说话人改名**：转写里的说话人一开始叫「说话人 1」「说话人 2」。在会议页面「转写」标签里给他们改成真名，转写和纪要里的称呼一起换掉（纪要会存成一个新版本）。
- **记住说话人**：管理员在「设置 → 声纹」里打开以后，给说话人改过一次名字，之后的会议就能按声音认出这个人，自动用这个名字，纪要里也直接写名字。自动起的名字标着「按声音认出」，认错了改过来就行，改对的名字下次认得更准。默认关着：声纹是从说话里算出的一串数字，不能还原成声音，只存在你的服务器上；关着时一点都不存，也可以随时在设置里删掉某个人的或者全部的声纹。
- **导出**：会议页面右上角「导出」，纪要可以导出成 Word 或 Markdown，转写可以导出成 Word 或纯文本（每句带时间和说话人）。
- **纪要模板**：内置通用会议、周会、技术评审、客户访谈四种，上传、录音、重新生成纪要时选。管理员可以在「设置 → 纪要模板」里加自己的模板，写清楚纪要要有哪几部分、每部分写什么。模板改了只影响以后生成的纪要；删掉以后，选过它的会议重新生成时改用通用模板。
- **录音保留期**：录音文件默认保留 90 天，过了只删录音，转写和纪要一直留着，照样能看、能搜（只是不能再回放、重新转写）。管理员在「设置 → 录音保留」里改，可以设成一直保留。
- **删除**：创建者和管理员可以删除会议。删掉的会议放进「回收站」（会议列表右边），30 天内可以恢复，过期后连同录音一起彻底删除，也可以在回收站里立即彻底删除。管理员看得到所有人删的会议，其他人只看得到自己创建的。已经发到飞书群的卡片、导入的飞书文档、发到钉钉 / 企业微信 / Slack 群里的消息不会跟着删除，需要的话在那边删。

### 成员

zsmeet 不发邮件。邀请同事、帮人重置密码，都是由管理员生成一个一次性的链接，再自己通过飞书、微信等发给对方。

- **邀请**：「设置 → 成员 → 邀请成员」，填对方的邮箱、选角色，得到一个邀请链接（7 天内有效，只能用一次）。对方打开后填姓名和密码就加入了。链接只在生成时显示一次；弄丢了或者过期了，在「还没接受的邀请」里重新生成。
- **角色**：成员可以上传会议、查看团队里的会议。管理员还能管理成员、配置大模型，看得到所有会议。
- **谁能看、谁能改会议**：会议默认团队里所有人都能看，只有创建者和管理员能改。创建者可以在会议页面上点「设置谁能看」，改成只有指定的人能看、或者只有自己能看（管理员总能看到），也可以指定谁还能编辑（改标题、编辑纪要、重新生成、给说话人改名、发到飞书和群里）。上传录音、网页录音时也可以直接选「只有我」。删除会议、改谁能看只有创建者和管理员能做。看不到的会议在列表和搜索里都不出现。
- **忘了密码**：管理员在成员列表里点「重置密码」，把生成的链接（24 小时内有效）发给他。自己记得密码、只是想换，在「设置 → 账号」里改。改密码后，这个账号在其他设备上的登录会全部退出，已登录的 App 也会退出。
- **有人离开团队**：在成员列表里停用他。他会立刻被退出登录（包括已登录的 App），之后也登录不了；他创建的会议都还在。以后重新启用的话，他需要重新登录，停用前的登录不会恢复。
- **链接的安全**：拿到重置密码链接的人能直接进那个账号，所以成员列表会显示谁名下有一个还没用的，可以随时撤销。管理员被降级或停用时，他发出去还没用掉的邀请和重置链接会一起失效；邀请还留在「还没接受的邀请」里，别的管理员重新生成一个链接就能接着用。
- **登录有效期**：登录后 30 天内不用再输密码，到期重新登录。
- **密码输错太多次**：同一个账号 15 分钟内输错 5 次、或者同一个 IP 输错 20 次，就锁 15 分钟，锁着的时候密码对了也登录不了，网页上会提示还要等几分钟。有人故意不停地输错某个账号的密码、让它一直锁着的话，管理员可以在服务器上执行 `zsmeet unlock 邮箱` 马上解开（见下面），用重置密码的链接设了新密码也会解开。按 IP 计数要先配好反向代理，见上面「HTTPS」。

- **桌面版登录**：zsmeet 桌面版（macOS）不在 App 里输密码。点「在浏览器里登录」会打开 zsmeet 的网页，在网页上登录（密码、飞书都行），确认「允许 zsmeet 桌面版登录你的账号」以后，浏览器把一次性的授权码交回桌面版（会问要不要打开 zsmeet，选打开）。授权码 2 分钟内有效，只能用一次，而且只有发起登录的那个桌面版能用它换到登录凭证。登录着的电脑列在「设置 → 账号 → 已登录的 App」里，电脑丢了、不再用了，在那里点「退出」。改密码、用重置链接设新密码、被停用时，所有 App 都会退出。

没有管理员能登录了怎么办（唯一的管理员忘了密码，或者离职没交接）：在服务器上执行下面的命令。

```bash
cd zsmeet/deploy
docker compose exec api zsmeet reset-link 某人的邮箱   # 给这个账号生成重置密码的链接
docker compose exec api zsmeet make-admin 某人的邮箱   # 把这个账号设为管理员
docker compose exec api zsmeet unlock 某人的邮箱       # 解开这个账号的登录锁（密码输错太多次被锁住时）
```

### 飞书

管理员在「设置 → 飞书」里接上一个飞书企业自建应用（Lark 也一样）以后：

- **纪要推到群里**：纪要第一次生成后，自动把一张卡片发到默认的群（也可以关掉自动发送；只发团队里所有人都能看的会议）。卡片上是摘要和待办，按钮链接回 zsmeet 里的这场会议，能看完整纪要、点时间点听录音。能编辑这场会议的人也可以在会议页面点「发到飞书」，选别的群再发一次；纪要改过以后再发，卡片会标成「纪要已更新」。弹窗打开以后纪要又重新生成或者被人改过的话不发，提示先看一下新的那一版再发。后台发送时，把纪要传给飞书导入、给群开文档权限、发卡片之前都会再看一遍会议：会议删了，自动发送的会议改成了不是团队所有人可见，或者手动发送的人已经不能编辑这场会议（被取消了编辑权限、会议改成了他看不到的、账号被停用），就不再往下发（已经导入好的文档留在放文档的文件夹里，不再给群开权限），发送记录上写着原因。
- **导入成飞书文档**：发到群里时可以同时把纪要导入成一篇飞书文档，卡片上带着文档的链接。文档归应用所有，按月份放在应用自己的云空间里；发到的群里的人能看，也可以设成公司里拿到链接的人都能看。想放进自己的文件夹，把那个文件夹共享给一个有这个机器人的群（给编辑权限），再把文件夹的链接填到设置里。
- **自动导入飞书会议的录制**：飞书会议结束后，如果开了云录制、会议的组织者也是 zsmeet 的成员（按邮箱对应），录制会自动导入成这位成员的会议，转写、生成纪要，再按上面的设置推到群里。组织者不是成员的会议不导入，连主题都不记。飞书生成录制一般要几分钟到几十分钟，zsmeet 最多等 12 小时。
- **用飞书登录**：登录页上多一个「用飞书登录」，用飞书扫码，或者在飞书网页版已经登录时点一下就行。第一次登录时按飞书里的**企业邮箱**（公司发的飞书邮箱，飞书验证过）对应到成员，对应上以后记住这个飞书账号，之后两边改了邮箱也不影响。
  - 企业邮箱有一个还没接受的邀请：用飞书登录就直接加入，角色按邀请里的，邀请随之用掉。
  - 通讯录里的邮箱是飞书管理员填的、没有经过本人验证，不会拿来登录已有的账号，也不会用掉发到这个邮箱的邀请：登录页会提示他先用邮箱和密码登录（或者打开邀请链接），再关联飞书。
  - 成员可以在「设置 → 账号」里输入密码、点「关联飞书」，把飞书账号关联到自己的账号上（不看邮箱），也可以在那里解除。管理员可以在「设置 → 成员」里替成员解除（比如他换了飞书账号，而自动创建的账号又不知道密码）。
  - 飞书账号还不是成员时，默认不让登录、提示他请管理员邀请；也可以设成自动创建成员账号（邮箱用企业邮箱，没有时用通讯录里的邮箱）。停用的成员用飞书也登录不了。
  - 下面列的两个权限都要开通，否则同事在飞书的授权页上会看到 20027 报错，飞书登录和关联都用不了。公司没用飞书邮箱时拿不到企业邮箱，只有在「设置 → 账号」里关联过飞书的成员能用飞书登录。
  - 在账号页上关联飞书要先输入当前密码；改密码、用重置链接设新密码时，关联的飞书账号会一起解除。这样即使登录状态被别人拿到，他也没法把自己的飞书账号关联上来留作后门。

这些都只需要服务器能访问飞书（`open.feishu.cn`），不需要公网地址：接收会议结束的消息用的是飞书的长连接；用飞书登录时，飞书是让同事的浏览器跳回 zsmeet，也不需要从外网访问服务器。

**在飞书开发者后台创建应用**（[open.feishu.cn](https://open.feishu.cn/app)，Lark 是 [open.larksuite.com](https://open.larksuite.com/app)）：

1. 创建企业自建应用，在「添加应用能力」里添加**机器人**。把 App ID 和 App Secret 填进 zsmeet 的「设置 → 飞书」，点「测试连接」。
2. 在「权限管理」里开通需要的权限：
   - 发到群里：`im:message:send_as_bot`、`im:chat:readonly`
   - 导入成飞书文档：`docs:document.media:upload`、`docs:document:import`、`docs:permission.member:create`、`docs:permission.setting:write_only`、`drive:drive.metadata:readonly`、`space:folder:create`
   - 导入会议录制：`vc:meeting.all_meeting:readonly`、`vc:record:readonly`、`minutes:minutes.media:export`、`contact:user.email:readonly`，并把「妙记」和「通讯录」的数据范围设为全员
   - 用飞书登录：`contact:user.employee:readonly`（读企业邮箱，按它对应成员）、`contact:user.email:readonly`，并在「安全设置 → 重定向 URL」里添加 `zsmeet 的访问地址/api/auth/feishu/callback`（「设置 → 飞书」里打开飞书登录后会显示完整的地址，可以直接复制）；应用的可用范围要包括用 zsmeet 的同事
3. 要导入会议录制的话：先在 zsmeet 里打开「自动导入飞书会议的录制」并保存（zsmeet 会连上飞书），再到「事件与回调」里选「使用长连接接收事件」，添加事件 `vc.meeting.all_meeting_ended_v1`（飞书会议结束）。
4. 创建版本并发布，等企业管理员审核通过。之后加的权限和事件，也要再发布一个版本才生效。
5. 把机器人拉进要接收纪要的群。

zsmeet 的访问地址要填同事能打开的地址（卡片上的链接、用飞书登录完跳回来都用它），用飞书手机端看的话，手机也要能打开。飞书的卡片需要 7.20 以上的客户端。私有化部署的飞书可以在 `.env` 里用 `ZSMEET_FEISHU_BASE_URL` 指定开放平台的地址（用飞书登录时的授权页也在这个地址上）。

### 群机器人（钉钉 / 企业微信 / Slack）

不用建应用：在钉钉、企业微信或 Slack 的群里加一个自定义机器人（Slack 是 Incoming Webhook），管理员把它的 Webhook 地址填进「设置 → 群机器人」，纪要就能发到那个群。

- **发到群里**：消息里是会议标题、时间、时长、创建者、纪要的摘要和待办，和「查看完整纪要」的链接。能编辑这场会议的人在会议页面点「发到群里」，可以一次勾几个群；每个群最近一次发没发成功、为什么失败，都在那里看得到。等着重试期间发的人已经不能编辑这场会议了（被取消了编辑权限、会议改成了他看不到的、账号被停用），就不再发。
- **自动发送**：给某个群打开「纪要生成后自动发到这个群」，每场会议第一次生成纪要后自动发一次（重新生成的不发）。和飞书一样，只自动发团队里所有人都能看的会议。
- **链接用的地址**：在「设置 → 群机器人」里填 zsmeet 的访问地址（同事们打开 zsmeet 用的地址），保存以后才生效；页面上会建议你现在打开 zsmeet 用的地址，点「填入这个地址」再保存。没保存时用飞书设置里的，都没有的话消息里不带链接，页面上会提示。
- **钉钉的安全设置**：钉钉要求机器人选一种安全设置。选「加签」的话，把 SEC 开头的密钥一起填进来；选「自定义关键词」的话，加一个关键词「会议纪要」（zsmeet 发的消息都带着这四个字）；选「IP 地址」的话填服务器的出口 IP。填好后点「发一条测试消息」，没发出去会说是哪一项不对。
- **安全**：拿到 Webhook 地址的人就能往群里发消息，所以地址和加签的密钥都加密保存，网页上只显示打了码的地址。只接受各平台官方的地址（`oapi.dingtalk.com`、`qyapi.weixin.qq.com`、`hooks.slack.com`，都要 https），填错或者被改成别的网站也不会把纪要发出去。

服务器要能访问这几个地址，不需要公网地址。网络不通、对方出错时会自动重试几次。各平台都限制每个机器人每分钟发 20 条左右：企业微信、Slack 限流时等 1 分钟再试；钉钉限流以后 10 分钟内都发不出去，所以等 11 分钟再试。自动重试最晚在开始发送后 25 分钟；发送中超过半小时的（比如服务器重启时丢了）算作失败，可以重新发。

### 搜索

在会议列表的搜索框里输入关键词，会在所有会议的标题、纪要和转写原文里找：

- **直接跳到说这句话的地方**：每场会议下面列出命中的句子和时间点，点一下就进入会议，从这句话前几秒开始播放，转写也滚到这一句。纪要里命中的条目带着时间点的，同样能跳过去。
- **听错的字也能搜到**：转写难免把专有名词听错（比如「飞书」听成「非书」）。写纪要时大模型会顺便列出会上专有名词的正确写法和听错的写法，搜「飞书」时，连转写里写成「非书」的地方也会找出来。
- **长词错一个字也算**：4 个字以上的中文词，转写里错了一个字的也会列出来，标着「近似」，排在完全命中的后面（错一个字的也可能是别的词，比如「项目经理」和「项目管理」）。
- **几个词用空格隔开**：每个词都在会议里出现过就算找到，不要求在同一句话里；同一句里都有的排在前面。中文和英文之间有没有空格都一样（「Go 语言」和「Go语言」），英文要整个单词对上（搜「AI」不会找到 email）。

搜的是字面，不是意思：讨论了某个话题但没说出那个词时，转写里搜不到，可以靠纪要（纪要按话题总结，每条都标了时间点）。

以前的会议是用旧的识别模型转写的，只有大段的时间。在会议页面的「转写」标签旁边点「重新转写」，就能用现在的模型重新转写，得到逐句的时间（会重新生成一版纪要，之前的版本都保留）。

### 问会议

配置了大模型以后，会议列表的搜索框旁边有「问会议」：用一句话提问，比如「上周关于报价定了什么？」，大模型从会议的纪要和转写里找答案。

- **带出处**：回答里的 [1] [2] 是出处，下面列着是哪场会议、几分几秒、原话是什么。点一下就进入那场会议，从说这句话的地方开始听。
- **怎么找的**：大模型先从问题里挑出搜索词（人名、产品、具体的事），问题里说了「上周」「十月」这样的时间就只看那段时间的会议；再用上面的搜索找出最相关的几场会议，把命中的纪要和转写前后几句交给大模型回答。大模型没按要求给出搜索词（或者太久没回）时，从问题里去掉「什么」「上周」「我们」这类词，拆出几个短词去搜。回答下面会写搜了哪些词，没找到想要的就换成会上可能原样说过的词再问。
- **只问一场会议**：会议页面上点「问这场会议」。会议不太长时整场的纪要和转写都交给大模型；点出处直接在这个页面上跳到那句话并开始播放，再点一次就从那句重新听。
- **只用你能看的会议**：看不到的会议不会被拿去回答，也不会出现在出处里。
- **会答错**：回答是大模型写的，只根据找到的那些片段；找不到时它会说没找到。重要的事请点出处核对原话。每人每分钟最多问 6 次。

和写纪要一样，问题和找到的会议片段会发给你配置的大模型。

### 处理要多久

识别在 CPU 上跑，不需要显卡。一组参考数据（Apple Silicon 笔记本上的 Docker，4 个线程，一段 20 分钟的两人对话）：

| 步骤 | 用时 |
|---|---|
| 接收与转码 | 9 秒 |
| 识别文字 | 13 秒 |
| 区分说话人 | 46 秒 |
| 合计（不含写纪要） | 约 1 分 10 秒 |

写纪要的时间取决于你用的大模型。普通的 x86 服务器会比这慢。

内存：worker 加载模型后常驻约 1 GB。另外一场录音会整段读进内存，每小时约占 230 MB，所以单场上限是 6 小时。

## 桌面版（macOS）

macOS 14.4 及以上，Apple 芯片和 Intel 都能用。它连的是团队自己部署的 zsmeet 服务器：看会议、搜索、问会议、上传录音、导出，和网页版一样；打开过的会议在断网时也能看。它还能录电脑里会议软件（飞书、腾讯会议、Zoom 这些）的声音和麦克风，断网也能录，联网后自动补传。设计见 [docs/desktop.md](docs/desktop.md)。

**安装**：在 [Releases](https://github.com/ZaneXo/zsmeet/releases) 里找 `desktop-v` 开头的版本，下载 `zsmeet-desktop-…-macos-universal.dmg`，打开后把 zsmeet 拖进「应用程序」。目前的安装包没有签名，第一次打开时 macOS 会提示「无法验证开发者」：在「应用程序」里右键点 zsmeet →「打开」，再点一次「打开」（只用做一次）。新版本的 macOS 上如果没有「打开」按钮，到「系统设置 → 隐私与安全性」最下面点「仍要打开」。

**第一次打开**：

1. 填服务器地址，也就是在浏览器里打开 zsmeet 用的地址（比如 `https://meet.example.com`）。没写 `http://` 或 `https://` 时先试 https，连不上再试 http。服务器要先在网页上完成初始化，并且是支持桌面版的版本。
2. 点「在浏览器里登录」：浏览器会打开 zsmeet 的登录页，用密码或飞书登录后点「允许」，浏览器会跳回 App，就登录好了。App 里不输密码。浏览器问「要打开 zsmeet 吗」时点允许。
3. 登录信息存在 macOS 的钥匙串里（名称是 `io.github.zanexo.zsmeet`，账户是服务器地址），下次打开不用再登录。重新安装新版本后第一次打开，macOS 可能会问是否允许 zsmeet 使用钥匙串里的这一项，点「允许」或「始终允许」（没签名的 App 每个版本在系统看来都是新的）。

**用起来和网页版的不同**：

- 关掉窗口 App 不退出，留在菜单栏里（菜单栏图标 →「打开 zsmeet」）；要退出用菜单栏图标 →「退出」或者 ⌘Q。
- 导出纪要、转写时弹出保存对话框；纪要里的链接用系统浏览器打开。
- 「设置」里只有账号：能看到连的哪台服务器、退出登录、切换服务器。改密码、关联飞书，以及管理员的团队设置，点「在网页里打开」到浏览器里做。在网页上改了密码，或者在账号页退出了这台电脑，App 会回到登录页。
- **离线**：连不上服务器时，会议列表、会议详情、纪要、转写这些打开过的内容照样能看，顶上显示「离线，显示的是上次同步的内容」，连上以后自动更新。没打开过的会议、录音回放、导出、修改都要等连上服务器。离线内容存在这台电脑上（每个用户最多约 256 MB），退出登录或切换服务器时删掉。

**录音**：

1. 点「开始录音」，填标题、选纪要模板和谁能看（和网页录音一样），再选录什么声音：
   - **电脑里的声音**：飞书、腾讯会议、Zoom 这些会议软件里其他人说话的声音（电脑上同时在放的别的声音也会录进去）。
   - **麦克风**：你自己和身边的人说话的声音。可以选用哪个麦克风，也可以不录。开线上会议时建议戴耳机，不然对方的声音从扬声器放出来，会被麦克风再录一遍。
2. 第一次录音时 macOS 会问两次，都点「允许」：是否允许 zsmeet 使用麦克风，是否允许 zsmeet 录制电脑的声音（系统音频）。点了「不允许」的话，录音页会提示去哪里打开：
   - 麦克风：「系统设置 → 隐私与安全性 → 麦克风」，打开 zsmeet。
   - 电脑里的声音：「系统设置 → 隐私与安全性 → 屏幕与系统录音」，在「仅系统录音」里打开 zsmeet。

   打开以后重新开始录音。只给了一项权限也能录，只是只录到那一路的声音。
3. 录音时可以暂停（暂停的时候什么都不录）、继续、标记重点（写纪要时会重点写这些时间点前后的内容）。关掉窗口录音也不停：菜单栏的 zsmeet 图标旁边显示录了多久，点开可以暂停、标记重点、结束录音。
4. 结束录音以后，剩下的部分传完，服务器自动开始转写、生成纪要，录音页上有这场会议的链接。一场最长约 6 小时，到时自动结束。

断网、退出和意外中断：

- 开始录音时要连得上服务器（先在服务器上建好这场会议）；开始以后断网照样录。录音每 10 秒左右存一片在这台电脑上，边录边传，断网时先存着，连上以后自动补传。
- 退出 zsmeet（菜单栏的「退出」或 ⌘Q）会先结束录音；没传完的部分下次打开 zsmeet 时接着传。
- 录到一半 zsmeet 意外退出、电脑断电：已经录好的部分都在。再打开 zsmeet 时会提示这场录音中断了，可以「接着录」（接在后面，标记的重点也都在），也可以「传上去生成纪要」，或者删掉。
- 录音的电脑找不回来了（丢了、坏了、一直连不上网）：已经传到服务器的部分还在。会议的创建者或管理员在网页上（或者另一台电脑的 zsmeet 里）打开这场会议，可以先用已经收到的部分生成纪要。那台电脑上还没传上来的部分就用不上了，它之后再打开 zsmeet 会显示这段录音传不上去，删掉就行。
- 退出登录、切换服务器会先结束正在录的那一场（点的时候会先提醒你）。录好的留在这台电脑上，以后用这个账号登录这台服务器时接着传，换别的账号登录看不到、也不会传。
- 录音存在 `~/Library/Application Support/io.github.zanexo.zsmeet/recordings/` 下，只有你自己的 macOS 账户能打开。传上去的分片先留着，等服务器确认整场都收到、开始处理以后才整个删掉（万一有一片其实没传成功，还能补传）；6 小时的录音大约占 170 MB。

**开发**：需要 Rust（[rustup](https://rustup.rs)，版本由 `desktop/src-tauri/rust-toolchain.toml` 固定）和上面「开发」一节的 Node + pnpm。

```bash
make desktop-dev        # 打开桌面版窗口，界面（web/）改了自动刷新。先用 make dev-api 起好服务器
make desktop-test       # 录音小程序的测试，cargo fmt、clippy 和 Rust 的测试（不碰钥匙串，用假的服务器），再和真的录音小程序一起录一遍（用测试音频，不要权限）
make desktop-build      # 构建本机架构的 .app 和 DMG，在 desktop/src-tauri/target/release/bundle/ 下
make desktop-universal  # 构建 Apple 芯片和 Intel 通用的 DMG，和发布时一样
```

开发模式下（`make desktop-dev`）macOS 不会把 `zsmeet://` 的链接交给它，浏览器登录完跳不回来：要试登录，用 `make desktop-build` 打出来的 App。界面里网页版和桌面版不一样的地方都在 `web/src/platform/`；网页版的构建（`pnpm -C web build`）里没有桌面版的代码。

录音小程序 `zsmeet-recorder` 在 `desktop/recorder/`（Swift，只装 Xcode 的 Command Line Tools 就能编），`desktop/scripts/build-recorder.sh` 构建它（`make desktop-dev`、`make desktop-build` 会自动构建），`desktop/recorder/test.sh` 跑它自己的测试（要 ffmpeg）。开发模式下录音的权限算在终端头上（系统设置里要打开的是终端），要试真的麦克风和电脑声音，用 `make desktop-build` 打出来的 App。

## 它是怎么工作的

```
浏览器 ──分片上传──▶  api（zsmeet serve）  ──任务入队──▶  Postgres
   ▲                    网页 · 接口 · 登录                    │
   │                                                          ▼
   └──── 进度推送 ◀──── 读数据库里的进度 ◀──── worker（zsmeet worker）
                                              拼接分片 → ffmpeg 转码 → 识别文字
                                              → 区分说话人 → 大模型写纪要
```

- `api` 和 `worker` 是同一个程序的两种启动方式，镜像也是同一个。
- 任务队列用 [River](https://riverqueue.com)，任务就存在 Postgres 里，不需要 Redis。
  「把会议改成排队中」和「任务入队」在同一个事务里，不会出现改了状态却没有任务的情况。
- worker 处理期间定时写心跳。worker 被杀掉或者机器重启时，心跳一停，巡检任务会在两三分钟内把会议重新入队，不用人工处理。
- 语音识别用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)：Silero VAD 切出有人说话的片段，SenseVoice 识别成带标点的文字（数字写成阿拉伯数字，每个字都有时间），按标点切成句子，pyannote + CAM++ 区分说话人。打开了声纹的话，再用 CAM++ 给每位说话人算一个声音特征，和改过名的人比对。
- 转写按句存，每句都有开始和结束时间：搜索命中、点击跳转、播放高亮都精确到句。

```bash
make api NAME=DeleteMeeting METHOD=DELETE ROUTE=/api/meetings/{id}
```

会生成 `internal/api/delete_meeting.go`（输入输出结构体、接口说明、返回 501 的处理函数）和对应的测试，并注册好路由。接下来：

1. 在生成的文件里填请求和返回的字段。这些结构体就是前后端的约定，参数校验和接口文档都从它来。
2. 在 `internal/service` 里写业务逻辑，处理函数里调用它。
3. 补测试，然后 `make gen`：接口文档（`web/openapi.json`）和前端的 TypeScript 类型（`web/src/api/schema.d.ts`）会一起更新。前端用到了改动的字段，编译时就会报错。

改数据库：在 `internal/db/migrations` 里加一个迁移文件，在 `internal/db/queries` 里写 SQL，然后 `make gen`。

### 几条约定

- 接口框架 huma 只出现在 `internal/api` 里，业务逻辑写在 `internal/service`。有测试守着这条规则（`internal/arch`），以后要换框架只需要重写接口层。
- 给用户看的文字（报错、提示）都写成能照着处理的中文，不把内部报错直接抛给用户。
- 参数校验没通过、请求内容不是 JSON 这类进不到处理函数、被 huma 直接挡下的请求，报错也换成了中文（`internal/api/problem.go`）：`detail` 是一句说清楚哪一项不对、怎么改的话（「标题太长了，最多 200 个字」），网页和桌面版直接显示它。加接口时，用户在网页上自己填的字段，要把它在界面上的叫法加进 `fieldNames`，没加的报错里写字段名。升级 huma 以后跑一遍测试：它新加的校验提示还没有中文时，测试会失败。
- 生成的文件（sqlc 的代码、`openapi.json`、`schema.d.ts`）都提交进仓库，`make test` 和 `make check` 会检查它们是不是最新的。
- 前端不依赖 React 的小函数可以在旁边写 `*.test.ts`，用 Node 自带的测试运行（`pnpm -C web test`，`make test` 会跑）；测试里 import 要带 `.ts` 后缀，被测的文件引用别的文件里的值（不只是类型）时也要带。
- 网页里的站内链接用 `AppLink`（`web/src/components/AppLink.tsx`），不直接用 react-router 的 `Link`：用户按住 Option 点 `Link` 时，浏览器会下载一个没用的网页空壳。`make check` 会检查。

### 发布

每次 push 到 main、每个 PR，GitHub Actions 都会跑一遍 `make check` 和 `make test`（`.github/workflows/ci.yml`）。

发新版本就推一个 v 开头的标签：

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Actions（`.github/workflows/release.yml`）会先跑一遍检查和测试，再分别在 amd64 和 arm64 的机器上构建镜像（识别库通过 cgo 调用，不交叉编译），合成一个多架构镜像推到 `ghcr.io/zanexo/zsmeet`，打上 `0.1.0`、`0.1`、`latest` 三个标签（`v0.2.0-rc.1` 这样带「-」的预发布版本只打它自己的版本号），最后发一个 GitHub Release。在 Actions 页面手动运行 Release 时只试着构建两种架构，不推镜像、不发 Release。

桌面版单独发布，推一个 desktop-v 开头的标签（版本号要和 `desktop/src-tauri/tauri.conf.json`、`Cargo.toml` 里的一致）：

```bash
git tag desktop-v0.1.0 && git push origin desktop-v0.1.0
```

Actions（`.github/workflows/desktop.yml`）跑完检查和测试，在 macOS 上打一个通用的 DMG，附到这个标签的 Release 上（不会顶掉服务器版本的「Latest」）。默认是 ad-hoc 签名；在仓库的 Secrets 里配了 Apple 的证书（`APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`）和公证用的账号（`APPLE_ID`、`APPLE_PASSWORD`、`APPLE_TEAM_ID`）以后，自动签名并公证，说明写在 workflow 文件开头。平时改了 `desktop/` 或 `web/` 的 PR 也会跑一遍桌面版的检查和测试。

第一次发布后如果别人拉镜像提示没有权限，说明镜像还是私有的：在仓库主页右边的 Packages 里打开 zsmeet，到 Package settings 把 Visibility 改成 Public（只用改一次）。

### 代码审查

PR 由 [CodeAnt AI](https://www.codeant.ai) 自动做 AI 代码审查，审查意见写成 PR 评论。审查要求放在 `.codeant/` 目录里：

- `instructions.json`：审查用中文、意见怎么写。
- `review.json`：按目录检查的项目规矩，比如会议的权限规则、迁移只加不改、后台任务的 run_id。
- `configuration.json`：不审查的文件，也就是生成的代码和锁文件。CodeAnt 的两份文档写法不一样，所以 `review_configuration`（PR 审查用）和 `file_filters`（代码扫描用）都写了。

它是一个 GitHub App，不跑在 Actions 里，只审查 PR，直接 push 到 main 的提交不审查。fork 的仓库要用，得自己在 codeant.ai 装。

已知的不足：

- 说话人区分的聚类阈值只在合成语音上调过，还需要用真实的多人会议校准（`internal/asr/asr.go`）；按声音认出说话人的阈值也一样（`internal/voiceprint`）。
