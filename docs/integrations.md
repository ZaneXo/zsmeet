# 飞书和群机器人

纪要可以推到飞书群、导入成飞书文档，飞书会议的录制可以自动导入，同事可以用飞书登录；纪要也能发到钉钉、企业微信、Slack 的群里。都在「设置」里由管理员配置。

## 飞书

管理员在「设置 → 飞书」里接上一个飞书企业自建应用（Lark 也一样）以后：

- **纪要推到群里**：纪要第一次生成后，自动把一张卡片发到默认的群（也可以关掉自动发送；只发团队里所有人都能看的会议）。卡片上是摘要和待办，按钮链接回 zsmeet 里的这场会议，能看完整纪要、点时间点听录音。能编辑这场会议的人也可以在会议页面点「发到飞书」，选别的群再发一次；纪要改过以后再发，卡片会标成「纪要已更新」。弹窗打开以后纪要又重新生成或者被人改过的话不发，提示先看一下新的那一版再发。后台发送时，把纪要传给飞书导入、给群开文档权限、发卡片之前都会再看一遍会议：会议删了，自动发送的会议改成了不是团队所有人可见，或者手动发送的人已经不能编辑这场会议（被取消了编辑权限、会议改成了他看不到的、账号被停用），就不再往下发（已经导入好的文档留在放文档的文件夹里，不再给群开权限），发送记录上写着原因。
- **导入成飞书文档**：发到群里时可以同时把纪要导入成一篇飞书文档，卡片上带着文档的链接。文档归应用所有，按月份放在应用自己的云空间里；发到的群里的人能看，也可以设成公司里拿到链接的人都能看。想放进自己的文件夹，把那个文件夹共享给一个有这个机器人的群（给编辑权限），再把文件夹的链接填到设置里。
- **自动导入飞书会议的录制**：飞书会议结束后，如果开了云录制、会议的组织者也是 zsmeet 的成员（按邮箱对应），录制会自动导入成这位成员的会议，转写、生成纪要，再按上面的设置推到群里。组织者不是成员的会议不导入，连主题都不记。飞书生成录制一般要几分钟到几十分钟，zsmeet 最多等 12 小时。
- **用飞书登录**：登录页上多一个「用飞书登录」，用飞书扫码，或者在飞书网页版已经登录时点一下就行。第一次登录时按飞书里的**企业邮箱**（公司发的飞书邮箱，飞书验证过）对应到成员，对应上以后记住这个飞书账号，之后两边改了邮箱也不影响。
  - 企业邮箱有一个还没接受的邀请：用飞书登录就直接加入，角色按邀请里的，邀请随之用掉。
  - 通讯录里的邮箱是飞书管理员填的、没有经过本人验证，不会拿来登录已有的账号，也不会用掉发到这个邮箱的邀请：登录页会提示他先用邮箱和密码登录（或者打开邀请链接），再关联飞书。
  - 成员可以在「设置 → 账号」里输入密码、点「关联飞书」，把飞书账号关联到自己的账号上（不看邮箱），也可以在那里解除。管理员可以在「设置 → 成员」里替成员解除（比如他换了飞书账号，而自动创建的账号又不知道密码）。
  - 飞书账号还不是成员时，默认不让登录、提示他请管理员邀请；也可以设成自动创建成员账号（邮箱用企业邮箱，没有时用通讯录里的邮箱）。停用的成员用飞书也登录不了。
  - 下面列的两个权限都要开通，否则同事在飞书的授权页上会看到 20027 报错，飞书登录和关联都用不了。公司没用飞书邮箱时拿不到企业邮箱，只有在「设置 → 账号」里关联过飞书的成员能用飞书登录。
  - 在账号页上关联飞书要先输入当前密码；改密码、用重置链接设新密码时，关联的飞书账号会一起解除。这样即使登录状态被别人拿到，他也没法把自己的飞书账号关联上来留作后门。

这些都只需要服务器能访问飞书（`open.feishu.cn`），不需要公网地址：接收会议结束的消息用的是飞书的长连接；用飞书登录时，飞书是让同事的浏览器跳回 zsmeet，也不需要从外网访问服务器。

**在飞书开发者后台创建应用**（[open.feishu.cn](https://open.feishu.cn/app)，Lark 是 [open.larksuite.com](https://open.larksuite.com/app)）：

1. 创建企业自建应用，在「添加应用能力」里添加**机器人**。把 App ID 和 App Secret 填进 zsmeet 的「设置 → 飞书」，点「测试连接」。
2. 在「权限管理」里开通需要的权限：
   - 发到群里：`im:message:send_as_bot`、`im:chat:readonly`
   - 导入成飞书文档：`docs:document.media:upload`、`docs:document:import`、`docs:permission.member:create`、`docs:permission.setting:write_only`、`drive:drive.metadata:readonly`、`space:folder:create`
   - 导入会议录制：`vc:meeting.all_meeting:readonly`、`vc:record:readonly`、`minutes:minutes.media:export`、`contact:user.email:readonly`，并把「妙记」和「通讯录」的数据范围设为全员
   - 用飞书登录：`contact:user.employee:readonly`（读企业邮箱，按它对应成员）、`contact:user.email:readonly`，并在「安全设置 → 重定向 URL」里添加 `zsmeet 的访问地址/api/auth/feishu/callback`（「设置 → 飞书」里打开飞书登录后会显示完整的地址，可以直接复制）；应用的可用范围要包括用 zsmeet 的同事
3. 要导入会议录制的话：先在 zsmeet 里打开「自动导入飞书会议的录制」并保存（zsmeet 会连上飞书），再到「事件与回调」里选「使用长连接接收事件」，添加事件 `vc.meeting.all_meeting_ended_v1`（飞书会议结束）。
4. 创建版本并发布，等企业管理员审核通过。之后加的权限和事件，也要再发布一个版本才生效。
5. 把机器人拉进要接收纪要的群。

zsmeet 的访问地址要填同事能打开的地址（卡片上的链接、用飞书登录完跳回来都用它），用飞书手机端看的话，手机也要能打开。飞书的卡片需要 7.20 以上的客户端。私有化部署的飞书可以在 `.env` 里用 `ZSMEET_FEISHU_BASE_URL` 指定开放平台的地址（用飞书登录时的授权页也在这个地址上）。

## 群机器人（钉钉 / 企业微信 / Slack）

不用建应用：在钉钉、企业微信或 Slack 的群里加一个自定义机器人（Slack 是 Incoming Webhook），管理员把它的 Webhook 地址填进「设置 → 群机器人」，纪要就能发到那个群。

- **发到群里**：消息里是会议标题、时间、时长、创建者、纪要的摘要和待办，和「查看完整纪要」的链接。能编辑这场会议的人在会议页面点「发到群里」，可以一次勾几个群；每个群最近一次发没发成功、为什么失败，都在那里看得到。等着重试期间发的人已经不能编辑这场会议了（被取消了编辑权限、会议改成了他看不到的、账号被停用），就不再发。
- **自动发送**：给某个群打开「纪要生成后自动发到这个群」，每场会议第一次生成纪要后自动发一次（重新生成的不发）。和飞书一样，只自动发团队里所有人都能看的会议。
- **链接用的地址**：在「设置 → 群机器人」里填 zsmeet 的访问地址（同事们打开 zsmeet 用的地址），保存以后才生效；页面上会建议你现在打开 zsmeet 用的地址，点「填入这个地址」再保存。没保存时用飞书设置里的，都没有的话消息里不带链接，页面上会提示。
- **钉钉的安全设置**：钉钉要求机器人选一种安全设置。选「加签」的话，把 SEC 开头的密钥一起填进来；选「自定义关键词」的话，加一个关键词「会议纪要」（zsmeet 发的消息都带着这四个字）；选「IP 地址」的话填服务器的出口 IP。填好后点「发一条测试消息」，没发出去会说是哪一项不对。
- **安全**：拿到 Webhook 地址的人就能往群里发消息，所以地址和加签的密钥都加密保存，网页上只显示打了码的地址。只接受各平台官方的地址（`oapi.dingtalk.com`、`qyapi.weixin.qq.com`、`hooks.slack.com`，都要 https），填错或者被改成别的网站也不会把纪要发出去。

服务器要能访问这几个地址，不需要公网地址。网络不通、对方出错时会自动重试几次。各平台都限制每个机器人每分钟发 20 条左右：企业微信、Slack 限流时等 1 分钟再试；钉钉限流以后 10 分钟内都发不出去，所以等 11 分钟再试。自动重试最晚在开始发送后 25 分钟；发送中超过半小时的（比如服务器重启时丢了）算作失败，可以重新发。
